    file.cio

    Purpose¶

    file.cio is the master index of a SWAT+ project. It is the first file SWAT+ opens, and it must be in the run folder under that name. Each line names the files for one input category, so every other input file is reached through file.cio. The last six lines give optional folders for the weather data files and for the output files.

    Format¶

    Line 1 is a title and is skipped. Lines 2 to 26 each start with a category label and continue with file names in a fixed order. Lines 27 to 31 each give one weather data folder, and line 32 gives the output folder.

    The reader takes the lines by position. The category label is read and discarded, so its text is not checked, and the file names are matched to slots by their order on the line. Values are separated by spaces.

    • Write null for a file the project does not use. Most readers treat a name that does not exist in the run folder the same way as null and skip the file. The exceptions are listed under Missing and null files.
    • File names can be up to 25 characters long. Longer names are cut to 25 characters.
    • Each line must give at least as many names as its category has slots. If a line is short, the reader continues onto the next line to fill the missing slots, and every later line is then read one line out of step. Extra names at the end of a line are ignored.

    Unused slots¶

    These names are read from file.cio, but SWAT+ 62.0.1 never opens the file they name. Any name or null can be given.

    • connect: aquifer2d.con (slot 6).
    • routing_unit: rout_unit.dr (slot 4).
    • herd: all three slots.
    • hru_parm_db: metals.mtl and salt.slt (slots 6 and 7).
    • init: hmet_water.ini, salt_hru.ini and salt_water.ini (slots 9 to 11).
    • regions: ls_cal.reg and ch_catunit.ele (slots 5 and 6).

    Two of these files are read under a fixed name instead. When salts are simulated, the HRU salt initial conditions come from a file named salt_hru.ini in the run folder, whatever slot 10 of the init line says. Channel catchment unit elements come from a file named element.ccu.

    The climate line has no wind direction file. It has nine slots, and slot 3 is pet.cli.

    Missing and null files¶

    For most slots, a name of null or a name that does not exist in the run folder means the file is skipped and the related feature is off. Some files behave differently:

    • object.cnt: if it is missing or null, SWAT+ prints Cannot find object.cnt input file and stops.
    • carbon.bsn: read only when carbon = 2 in codes.bsn. It is then required, and SWAT+ stops with an error, written to the screen and to diagnostics.out, if the file named in slot 3 of the basin line does not exist or cannot be opened. The per-layer carbon file has no slot on the line: its name is built from the carbon file name, so carbon.bsn gives carbon_lyr.bsn.
    • time.sim and print.prt: there is no check for a missing file. If the name is not null and the file does not exist, SWAT+ creates an empty file of that name and continues with built-in values. For time.sim this leaves the run without a valid simulation period, so the file is required in practice.
    • place_of_use.wro and point_of_diver.wro: if either is missing or null, SWAT+ creates an empty file of that name (a file called null in the second case), reads nothing from it, and water allocation is off. See water allocation.
    • chan-surf.lin: if the name is not null and the file does not exist, SWAT+ creates an empty file of that name. See link files.

    Weather data folders¶

    Lines 27 to 31 let the precipitation, temperature, solar radiation, humidity and wind data files be kept outside the run folder. Each line has a label and one value of up to 80 characters. A value of null means the data files are in the run folder.

    SWAT+ joins the folder and the file name from the climate index file (for example pcp.cli) without adding a separator, so the folder must end with / or \. The folder is read in the same way as a file name, with two consequences:

    • A folder name that contains spaces must be in quotes.
    • An unquoted / ends the value. data/pcp/ is read as data, and an unquoted value that starts with / is read as empty, so the files are looked for in the run folder. Put any folder that uses forward slashes in quotes, for example "C:/swat/weather/pcp/", or use backslashes on Windows.

    There is no folder line for potential evapotranspiration data. Files listed in pet.cli are always read from the run folder.

    Output folder¶

    Line 32 is optional. It has a label (any word) and a folder name. SWAT+ reads the whole line, drops the first word and takes the rest of the line as the folder, so the folder name can contain spaces and forward slashes without quotes. Up to 256 characters are kept. If the line is missing or empty, or the folder is null or NULL, the output files are written to the run folder.

    When a folder is given, SWAT+ converts the separators to the ones the operating system uses, creates the folder and any missing parent folders, and prints Output path set to: with the folder name. A relative folder is taken from the run folder. On Linux and macOS a folder that contains : is treated as a Windows path, and SWAT+ stops with an error. On Windows a folder that starts with / is placed on drive C:. SWAT+ also stops if it cannot create or open the folder.

    The standard output files go to this folder, including files_out.out, diagnostics.out, checker.out and the time series outputs switched on in print.prt. In 62.0.1 the gwflow output files and the soft calibration output files (hru-out.cal, hru-new.cal and others) are still written to the run folder.

    Older file.cio files¶

    Two lines changed length in recent revisions, and a file.cio written for an earlier revision needs both updated before it is run with 62.0.1:

    • The basin line now has three slots. Add carbon.bsn or null after parameters.bsn. With only two names on the basin line, SWAT+ takes the first word of line 4 (climate) as the carbon file name and discards the rest of that line. Every later category is then read from the line below the one it belongs to: the climate files are taken from the connect line, the connection files from the channel line, and so on. No message reports the shift. If carbon = 2 in codes.bsn, SWAT+ stops with ERROR: climate is required when carbon is enabled; otherwise the run continues with wrong file names in every later slot.
    • The water_rights line (line 15) now has two slots, the place-of-use file and the point-of-diversion file. An older line with water_allocation.wro element.wro water_rights.wro makes SWAT+ read water_allocation.wro as the place-of-use file and element.wro as the point-of-diversion file, and the third name is ignored. See water allocation for those files.

    The basin line has three slots, with null for the carbon file because the project does not use the carbon model.
