    hru-data.hru

    Purpose¶

    hru-data.hru lists the HRU property sets of the project. Each row names one record in each of the parameter files an HRU needs: topography, hydrology, soil, land use and management, soil and plant initialization, surface storage (wetland), snow and field. An HRU picks its row through the hru column of hru.con, which gives the id of a row in this file. The file is named on the hru line of file.cio (default hru-data.hru).

    The parameter values themselves are in the files the names point to. This file only links them together, so several HRUs can share one hydrology or topography record while having different soils or land uses.

    Format¶

    Free format, whitespace-separated. Line 1 is a title and line 2 is the column header; both are skipped. Each later line is one property set with ten values in the order below. The reader does not match columns by header name, so all ten values must be present and in this order.

    # Column Looked up in Description
    1 id - Number of the property set. The hru column of hru.con refers to this value. The numbers do not have to be consecutive; the largest id sets the size of the table.
    2 name - Name of the property set, up to 40 characters. Not used in calculations.
    3 topo topography.hyd Topography record: slope, slope lengths and deposition coefficient.
    4 hydro hydrology.hyd Hydrology record: lateral flow, canopy storage, evaporation and percolation parameters.
    5 soil soils.sol Soil profile.
    6 lu_mgt landuse.lum Land use and management record, which sets the plant community, management schedule, curve numbers, conservation practices and structures such as tile drains.
    7 soil_plant_init soil_plant.ini (see initial conditions) Initial soil water, soil nutrients and constituents. The names of the soil test, pesticide, pathogen, heavy metal, salt and constituent records given in that row are matched at the same time.
    8 surf_stor wetland.wet Surface storage (wetland or paddy) record, or null for an HRU without surface storage.
    9 snow snow.sno Snow parameter set.
    10 field field.fld Field dimensions, or null to use the built-in values.

    A name must match the record name in the target file character for character, including case. Names in topography.hyd, hydrology.hyd and field.fld are stored with at most 16 characters and soil names with at most 20, so a longer name in this file can never match a record there.

    Name lookup¶

    Each name is looked up once, when the files are read. The table gives what happens when a name is not found:

    Column null or a name that is not found
    topo, hydro, soil, lu_mgt, soil_plant_init, snow The HRU uses the first record of the target file. No message is written.
    surf_stor null means no surface storage. Any other name that is not in wetland.wet is reported in diagnostics.out as <name> not found (wetland.wet) and the HRU has no surface storage.
    field The HRU uses the built-in field values (length 500 m, width 100 m, angle 30°). A name other than null that is not found is reported in diagnostics.out as <name> not found (field.fld).

    The reader has checks that would write not found messages for topo, hydro, soil, lu_mgt, soil_plant_init and snow, but they test for a pointer of zero while the pointers start at one, so in 62.0.1 these messages are never written. Check these names by hand, or in the SWAT+ Editor, before a run.

    For snow this means that null selects the first row of snow.sno, the same as an unmatched name. A project that has no snow.sno file at all has no first row to fall back on.

    The surf_stor name is matched when the wetlands are initialized, which happens only when wetland.wet has at least one record.

    Tile drainage¶

    The lu_mgt record decides whether an HRU has tile drains. For a tile-drained HRU, SWAT+ replaces two values from its hydro record at the start of the run: cn3_swf is set to 0.95 and perco to 0.1. Calibration changes to cn3_swf and perco are also skipped for these HRUs. See hydrology.hyd.

    Example¶

    refdata/Ames_sub1/hru-data.hru in the SWAT+ repository (first four rows):

    hru-data.hru: 
      id  name                          topo             hydro              soil            lu_mgt   soil_plant_init         surf_stor              snow             field  
       1  hru0001                topohru0001           hyd0001           soil_01-h1       cosy_lum        soilplant1              null           snow001              null  
       2  hru0002                topohru0002           hyd0002           soil_02          mntill_corn_lum soilplant1              null           snow001              null  
       3  hru0003                topohru0003           hyd0003           soil_03-h3       cosy_lum        soilplant1              null           snow001              null  
       4  hru0004                topohru0004           hyd0004           soil_04          cosy_lum        soilplant1              null           snow001              null

    Each HRU has a separate topography record, hydrology record and soil. HRU 2 uses the land use mntill_corn_lum, the others cosy_lum. No HRU has surface storage, all use the snow set snow001, and field is null, so every HRU uses the built-in field dimensions.

    Related files¶

    • hru.con: one row per HRU; its hru column selects a row of this file by id. The HRU's area, elevation, latitude and weather station come from hru.con.
    • object.cnt: number of HRUs.
    • topography.hyd, [hydrology.hyd](../input-reference/hyd.md#hydrologyhyd) and field.fld, soils.sol, landuse.lum, initial conditions, wetland.wet, snow.sno: the files the names point to.
    • file.cio: names this file on its hru line.
    • Water allocation: an HRU can be named as a point of diversion in point_of_diver.wro. That link is made in the water allocation files; there is no column for it here.
